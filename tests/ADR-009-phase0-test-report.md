## 二、測試結果

```
$ npm test
# tests 27
# suites 5
# pass 27
# fail 0
```

測的是 `apps-script/Code.gs` **本人**，不是抄出來的副本——`tests/fake-apps-script.mjs`
把原始碼整份載進一個假的 Apps Script 環境（Sheet 是二維陣列，列號語意、刪列位移
都跟真的一致）。抄一份出來測的話，兩份實作遲早漂移，測到的就不是上線那份了。

### 涵蓋範圍

**單欄鍵（ADR-007／ADR-008 既有行為的回歸，7 項）**
確認這次擴充沒有把既有的東西改壞：新鍵 append、既有鍵覆蓋不長新列、Sheet 存數字
而前端送字串仍視為同一筆、同鍵多列收斂成一列並寫 `logs`、沒有鍵欄時退回 append
且留 console、`key_field='line_id'` 的管理頁路徑照舊。

**複合鍵（ADR-009 §一.5 新能力，5 項）**
同一天不同人是兩筆不互相覆蓋、同一天同一人覆蓋既有列、Sheet 存 Date 物件仍對得上、
鍵欄之一是空的就退回 append 不跟別人撞鍵、Sheet 那列鍵不完整時也不會被當成匹配。

**墓碑過濾（3 項）**
`true`／`'TRUE'` 都濾掉、空白與「根本沒有 `del` 欄」都保留、空輸入不會爆。

**兩段式封存（7 項）**
只撈墓碑列、**清單是空的就一列都不刪**、只刪清單裡的、清單裡的列中途被取消 `del`
就放過它、一次刪多列時列號不位移刪錯人、刪了就寫 `logs`、reviews 用複合鍵也刪得準。

**欄位安裝（5 項）**
缺的補在最右邊且資料列不被碰到、重複執行不再變動、已有部分欄位時只補缺的、分頁
不存在就略過不建空表、連表頭都沒有就只回報不硬寫。

### 全綠不等於測到了：突變測試

「27 項全過」這句話本身沒有證據力——測試有可能只是寫得太鬆。所以故意把程式改壞
兩次，看測試抓不抓得到：

| 故意改壞的地方 | 結果 |
|---|---|
| 拿掉 `keyValue_` 的 Date 正規化 | ❌ 正好是「Sheet 把日期存成 Date 物件時仍然對得上」那一項失敗，其餘 26 項仍過 |
| 拿掉封存第二段「此刻仍是墓碑」那道鎖 | ❌ 正好是「清單裡的列中途被取消 del，就放過它」那一項失敗，其餘 26 項仍過 |

兩次都精準命中對應的那一項，沒有誤傷別人。改壞的檔案事後以 md5 確認還原無誤。

## 三、實作時發現、ADR 上沒寫到的事

### 1. ⚠️ 日期欄的型別陷阱（複合鍵的連帶代價，非做不可）

ADR 說 `reviews` 要用 `review_date + line_id` 當複合鍵。實作時發現一個 ADR 沒提、
但不處理就會直接廢掉這個鍵的問題：**Sheet 讀回來的 `review_date` 是 Date 物件，
前端送上來的是 `'2026-09-16'` 字串。** 直接 `String()` 會得到
`'Mon Sep 16 2026 00:00:00 GMT+0800'`，兩邊永遠對不上，於是每次 upsert 都退化成
append——正好是這次要根治的重複列，從另一個方向長回來。

處理方式：新增 `keyValue_()` 做正規化，Date 取**本地**年月日。刻意不用
`toISOString()`：那是 UTC，在 UTC+8 會把當天算成前一天。有專門一項測試盯著。

> 順帶一提，這跟安全性改善計畫裡的 **DATA-05（日期／compass／時間戳）** 是同一個
> 根。`doGet` 走 `JSON.stringify` 時 Date 會被轉成 UTC ISO 字串，前端 `slice(0,10)`
> 就可能拿到前一天。那條路徑今天沒動，列在下面的待辦裡。

### 2. `upsertRow_` 現在會 trim 鍵值（行為微調，刻意的）

舊版比對是 `String(record[key]) === String(cell)`，前後空白會讓兩個其實一樣的
`line_id` 對不上而多長一列。新版兩邊都 trim。這是往好的方向改，但確實是行為變動，
明講。

### 3. `findRowsById_` 被 `findRowsByKey_` 取代

舊函式只吃單欄，且只有 `upsertRow_` 一個呼叫端（已查證，兩個 `.gs` 全域都找過）。
留著會是死碼，所以直接換掉，不是新增第二套。

### 4. 「沒有 `del` 欄」一律當成沒刪

比照 ADR-008 E-2 的既有選擇（欄位不存在＝視為開放）。理由一樣：欄位安裝前全表照常
回傳，不會因為漏裝一個欄位，讓畫面看起來像資料全毀。

### 5. ⚠️ 與另一條分支的範圍重疊（需要你裁決）

Notion 上那份「2026-09-16 安全性與 Code Review｜改善計畫」正在
`codex/security-sync-hardening-20260916` 分支實作，其中 **DATA-01（多裝置更新、刪除
與整表覆寫）、DATA-03（寫入前驗證、鎖與恢復）、以及 tombstone** 跟 ADR-009 §一
講的是同一件事、會動到同一批程式碼。

今天這批改動刻意只新增函式、不接線，衝突面積因此很小。但**Phase 2 一旦開始改前端
五個模組的讀寫路徑，兩條分支就會正面對撞**。動工前需要你決定：先合併哪一條、或是
把兩者併成同一條線做。這是我今天唯一沒有自行決定的事。

## 四、要你手動做的兩件事（都不急，Phase 2 前做完即可）

### 1. 裝欄位

Apps Script 編輯器 → 選 `ensureAdr009Columns` → 執行 → 看執行記錄。

可以重複執行，已存在的欄位不會被動到。它只補表頭、往最右邊加，不碰任何資料列。
分頁不存在會略過（那五張表會在第一次同步時自己長出來）。

### 2. 測 LINE 推播（ADR-009 C5 的條件式決策）

Apps Script 編輯器 → 選 `testLinePush` → 執行 → 看手機有沒有收到訊息。

對象：優先讀指令碼屬性 `PUSH_TEST_TO`；沒設就自動抓 `line_users` 裡第一位啟用中的
管理者（也就是你），不必為了跑一次測試先去設一個屬性。

判讀：

- **HTTP 200** → push 可行，C5 通知功能照 ADR 實作
- **HTTP 400** → 多半是對象 userId 不對，或對方沒加官方帳號好友
- **HTTP 401** → 權杖問題，先跑 `diagnoseLineToken()`
- **HTTP 429** → 配額用完。這正是 ADR 說「則數不敷使用再重新評估 Web Push」的訊號

失敗的話依 ADR：通知那塊移入未來票，**C1-C4（到期日欄位、儀表板區塊視覺化）照常
上線，不因為 push 卡住被連帶延後。**

## 五、你點頭之後，Phase 2 會做什麼

依 ADR-009 的順序，且每一項都會先補測試：

1. `doGet` 對所有分頁過濾 `del=true`（待其他環境知道的事 #4）
2. 前端五個模組（tasks／expenses／reviews／notes／moods）改成即時單筆 upsert，
   拆掉 debounce 250ms + 整包 `replaceAll`
3. 刪除改為寫 `del`；離線時不顯示本機資料，改呈現連線異常
4. 15 秒輪詢 + 手動刷新按鈕，背景暫停
5. 兩段式封存接上前端 `exportData()` 下載成功訊號
6. 共用白板（`board` 欄）與週期提醒（`due_date` / `recur_*` / `notified`），
   共用同一張儀表板卡片橫向滑動
7. `ScriptApp.newTrigger()` 寫成程式碼裡的安裝函式（待其他環境知道的事 #5），
   不在編輯器手動加

順帶一提，這次也把 `npm test` 接進 CI，擋在 `clasp push` 前面——「測試失敗不部署」
是那份安全性改善計畫的放行條件之一，部署成功不能當驗收。
